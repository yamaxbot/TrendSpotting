# Веб-интерфейс TrendSpotting

> Историческое описание прототипа. Текущий путь запроса, модель и запуск: [README.md](README.md).

## Обновление: фоновый поиск

Поиск подключён к парсеру, CatBoost и LLM. Новый запрос запускается в фоновой
очереди одного процесса Django; браузер проверяет `/search/status/?q=...` каждые
три секунды. Готовый parquet используется при возврате на страницу результатов.
Одновременно выполняется одна задача, очередь ограничена десятью задачами.
При перезапуске сервера незавершённые задачи прерываются: страницу нужно обновить
или повторить поиск. Для многопроцессного production-развёртывания необходим
отдельный worker с общей очередью и постоянным хранилищем статусов.

Проверки без внешних API: `python website/manage.py test trends` из корня проекта.
Описание первоначального прототипа ниже оставлено как историческая справка.

## Назначение

Папка `website/` содержит локальный прототип веб-интерфейса «ТрендСкан». Он показывает результаты поиска слабых сигналов в научном корпусе и позволяет открыть подробности отдельного направления.

Текущая версия предназначена для демонстрации пользовательского сценария. Данные трендов пока задаются непосредственно в `website/trends/views.py`; подключение реального корпуса, обученной модели и фильтрации по поисковому запросу ещё не реализовано.

## Запуск

Из папки `website/`:

```bash
python manage.py runserver
```

После запуска интерфейс доступен по адресу `http://127.0.0.1:8000/`.

Для установки всех зависимостей проекта используется общий файл из корня:

```bash
pip install -r ../requirements.txt
```

## Логика работы

```text
HTTP-запрос
    ↓
Маршрутизация Django
    ↓
Представление dashboard или trend_detail
    ↓
Демонстрационный список TRENDS
    ↓
Шаблон Django
    ↓
HTML + static/css/site.css + static/js/site.js
```

### Главная страница

Маршрут `/` обрабатывает `trends.views.dashboard`:

- получает поисковый параметр `q`, по умолчанию используется `ИИ`;
- передаёт в шаблон список из 15 направлений;
- показывает количество публикаций, число направлений и период наблюдения;
- формирует карточки трендов с рейтингом, тематикой, направлением и уверенностью модели;
- сохраняет поисковый запрос при переходе на страницу подробностей.

Шаблон главной страницы — `templates/trends/dashboard.html`.

### Страница направления

Маршрут `/trend/<slug>/` обрабатывает `trends.views.trend_detail`:

- находит направление по `slug`;
- передаёт в шаблон описание, уверенность, динамику публикаций, факторы сигнала и источники;
- возвращает первое направление, если передан неизвестный slug;
- позволяет вернуться на главную страницу с сохранённым параметром `q`.

Шаблон страницы направления — `templates/trends/detail.html`.

## Результат

В результате создан интерфейс с двумя связанными экранами:

1. Главная страница с поисковой формой, сводными метриками, списком из 15 направлений и панелью аналитики.
2. Детальная страница с уровнем уверенности, графиком публикационной динамики, объяснением сигнала, прогнозирующими факторами и источниками.

Общий шаблон задаёт русскую локализацию, навигацию «Поиск трендов», ссылку «Как это работает» и подключение статических CSS/JavaScript-файлов. Настройки используют SQLite, `DEBUG=True` и локальные адреса, поэтому конфигурация подходит для разработки, но не предназначена для production-развёртывания.

## Ограничения и дальнейшее развитие

- `TRENDS` является статическим демонстрационным набором.
- Поиск принимает параметр `q`, но пока не фильтрует и не пересчитывает результаты.
- Значения публикаций, уверенности и графиков не загружаются из основного пайплайна.
- Модели Django для трендов не созданы; `db.sqlite3` не используется для хранения результатов анализа.
- Для рабочего режима нужно подключить экспорт из `data/`, реальную модель и безопасные настройки секретного ключа, `DEBUG` и `ALLOWED_HOSTS`.
