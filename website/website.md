# Сайт и выдача результатов

`website/` — Django-приложение, которое запускает поиск и показывает карточки кандидатов.

## Структура

| Путь | Роль |
|---|---|
| `manage.py`, `trendspotting/` | Точка входа Django, настройки, URL и WSGI |
| `trends/views.py`, `trends/urls.py`, `trends/jobs.py` | Страницы, API статуса и очередь фоновых поисков |
| `trends/evidence.py`, `trends/statistics.py`, `trends/charts.py`, `trends/organizations.py` | Близкие источники, тематическая статистика, графики и организации |
| `main.py`, `article_type.py`, `relevance_gate.py`, `diversity.py` | Признаки, CatBoost, отсев обзоров/нерелевантных статей и разнообразие ТОП-15 |
| `query_llm.py` | Перевод названий и тексты карточек через `qwen/qwen3.7-flash` и общий клиент `../vsellm_chat.py` |
| `templates/trends/`, `static/css/`, `static/js/` | HTML-шаблоны и оформление |
| `data/` | Генерируемые результаты запросов; не исходный код |
| `trends/tests.py` | Проверки страниц и логики поиска |

При запросе `jobs.py` запускает парсер, расчёт признаков, модель и подготовку текстов. `views.py` читает готовый Parquet и отдаёт карточки; страница статьи отдельно запрашивает источники и статистику. Отладочные JSON парсера пишутся в `logics/` относительно рабочего каталога (в Docker это `website/logics/`). Статусы задач хранятся в памяти одного процесса: при его перезапуске незавершённый поиск нужно повторить. Готовые файлы в `data/` используются повторно, если совпадают версии модели, отбора и текстов; карточка без переведённого названия считается незавершённой.

Запуск из корня проекта: `python website/manage.py runserver`. Тесты: `python website/manage.py test trends --noinput`. Настройка сервера и Docker — в [главном README](../README.md).
