# Предобработка данных для TrendSpotting

> Исторический baseline. Текущие точки входа и роль папки: [README.md](README.md).

## Назначение

Папка `preprocessing` содержит этап подготовки корпуса научных публикаций к последующему анализу и обучению модели. На этом этапе из исходного Parquet-файла формируется компактный набор из 13 колонок, включающий числовые признаки и целевую переменную `target_emergence`.

Текущая реализация предназначена для baseline-эксперимента на корпусе из 1 000 000 работ OpenAlex. Часть признаков вычисляется по доступной выборке, поэтому результаты следует интерпретировать как экспериментальные оценки, а не как окончательные характеристики всей базы OpenAlex.

## Вход и выход

## Целевая переменная ESI

Целевая переменная строится отдельно для каждой пары `(primary_topic_id, pub_year)`. Это означает, что метка характеризует не индивидуальную статью сама по себе, а развитие темы после года публикации статьи.

Для каждой темы и года `t` используются одинаковые по длине временные окна:

```text
past:   t-3, t-2, t-1
future: t+1, t+2, t+3
```

Год `t` не входит ни в одно из окон. Например, для статьи 2018 года:

```text
past:   2015, 2016, 2017
future: 2019, 2020, 2021
```

Одинаковая длина окон важна для сопоставимости. Если интенсивность публикаций или авторства постоянна, средние значения в двух окнах совпадают, а логарифмический рост стремится к нулю.

### Публикационный рост

Для темы `k` и года `t` вычисляются средние годовые количества публикаций:

$$
\overline{P}_{past} = \frac{1}{3}\sum_{y=t-3}^{t-1} P_{k,y}
$$

$$
\overline{P}_{future} = \frac{1}{3}\sum_{y=t+1}^{t+3} P_{k,y}
$$

Затем рассчитывается логарифмический прирост публикаций:

$$
 g_{pub} = \ln\left(\frac{\overline{P}_{future}+\varepsilon}{\overline{P}_{past}+\varepsilon}\right)
$$

В реализации используется малое сглаживание `epsilon = 1e-8`. Оно предотвращает деление на ноль для тем с отсутствующими публикациями в одном из окон.

### Рост авторского сообщества

Для каждого года считаются уникальные авторы темы. В исходном Parquet авторские идентификаторы могут быть представлены через `authors_ids` либо извлекаются из `authorships_json`.

Средние размеры авторского сообщества обозначаются как `A_past` и `A_future`:

$$
 g_{auth} = \ln\left(\frac{\overline{A}_{future}+\varepsilon}{\overline{A}_{past}+\varepsilon}\right)
$$

Абсолютное изменение авторского сообщества:

$$
 \Delta A = \overline{A}_{future} - \overline{A}_{past}
$$

### Emergence Synergy Index

Итоговый индекс рассчитывается по формуле:

$$
ESI = \operatorname{arcsinh}(g_{pub})
\cdot
\left(1 + \alpha\tanh(\max(0,g_{auth}))\right)
\cdot
\sigma\left(\beta\frac{\Delta A}{\sqrt{\overline{A}_{past}+\gamma}}\right)
$$

Используемые параметры:

```text
alpha = 0.5
beta  = 0.5
gamma = 1.0
```

Функции `arcsinh`, `tanh` и сигмоида ограничивают влияние экстремальных значений. Авторский рост усиливает индекс только при положительном `g_auth`, а масштабный множитель учитывает абсолютное изменение числа авторов относительно размера исходного сообщества.

### Бинарная метка

Для каждого года `t` порог определяется отдельно:

$$
Threshold_t = Quantile_{0.90}(\{ESI_{k,t}\})
$$

Затем:

$$
 target\_emergence =
 \begin{cases}
 1, & ESI_{k,t} \ge Threshold_t \\
 0, & ESI_{k,t} < Threshold_t
 \end{cases}
$$

Таким образом, положительный класс состоит из верхних 10% topic-year комбинаций по ESI в соответствующем году. Все статьи одной темы, опубликованные в одном году, получают одну и ту же метку.

Если для строки невозможно сформировать полные временные окна, `target_emergence` остаётся пустым (`NaN`/`pd.NA`). Такая строка не является отрицательным примером и не должна автоматически превращаться в класс 0.

## Вычисляемые признаки

### Авторский рост

`author_growth_rate` оценивает краткосрочную динамику числа уникальных авторов темы. Для текущего baseline используется логарифмическое сравнение авторских множеств в соседних прошлых годах. Значение рассчитывается только по информации, сохранённой в корпусе.

### Новизна текста

`novelty_raw` вычисляется на основе TF-IDF абстрактов:

1. строится TF-IDF-матрица с максимумом 2000 признаков;
2. для каждой темы рассчитывается средний TF-IDF-вектор, то есть центроид темы;
3. для каждой работы вычисляется косинусное сходство с центроидом своей темы;
4. новизна определяется как `1 - cosine_similarity`.

Расчёт выполняется по темам, чтобы не создавать огромную промежуточную sparse-матрицу при обработке миллиона строк.

### Плотность темы

`cluster_density` использует норму тематического центроида как приближённую оценку концентрации текстовых представлений внутри темы. Это текущий вычислимый proxy, а не полноценная плотность по расстояниям до ближайших соседей.

### Outlier-признак

`is_outlier_cluster` в текущем baseline является proxy для выброса. Работа помечается единицей, если её `novelty_raw` находится в верхних 5% значений внутри своей темы.

Этот признак не является результатом полноценного HDBSCAN или другой кластеризации. В будущей версии его можно заменить на point-in-time кластеризацию по embeddings или другой устойчивой структуре пространства признаков.

### Sample-based PPMI

`ppmi_domain_score` рассчитывается по доступным ссылкам внутри текущего корпуса. Для ссылки учитывается домен работы, на которую она указывает. Затем оценивается ассоциация между основной темой текущей работы и доменом найденной ссылочной работы:

$$
PPMI(x,y) = \max\left(0,\ln\frac{p(x,y)}{p(x)p(y)}\right)
$$

Поскольку миллионный корпус является выборкой, значительная часть ссылок указывает на работы, отсутствующие внутри него. Поэтому это sample-based оценка и не полная PPMI-статистика OpenAlex.

### Разнообразие источников

`distinct_venues_ratio` рассчитывается как отношение числа уникальных `source_id` среди найденных связанных работ к числу всех найденных связанных работ:

$$
DistinctVenuesRatio =
\frac{\left|Sources_{found}\right|}{\left|References_{found}\right|}
$$

Это proxy по исходящим ссылкам и доступным работам корпуса. Полноценная метрика разнообразия источников входящих цитирований потребует полного графа цитирования и метаданных всех цитирующих работ.

## Обработка памяти

В процессе разработки были устранены несколько проблем, связанных с размером корпуса:

- расчёт авторского роста больше не использует `DataFrame.apply(axis=1)`, который создавал большой object-массив;
- косинусное сходство считается по темам, а не через опасное broadcasting всей sparse-матрицы;
- исходные list-колонки читаются под каноническими именами Pandas;
- выходные признаки не запрашиваются из исходного Parquet до момента их вычисления;
- авторы извлекаются из `authorships_json`, если отдельной колонки `authors_ids` нет.

## Контроль качества

`dataset_check.py` выполняет статистический анализ обработанного набора данных:

```powershell
.\.venv\Scripts\python.exe .\preprocessing\dataset_check.py
```

Анализ включает проверку:

- размер датасета;
- распределение `target_emergence`;
- пропуски;
- описательные статистики признаков;
- различия распределений между классами;
- взаимную корреляцию признаков;
- распределение положительных примеров по `source_tier`.

При наличии частично размеченного корпуса статистические тесты выполняются только по строкам с рассчитанной целевой переменной `0/1`. Строки с `NaN` исключаются из анализа классов.

## Текущие ограничения

1. ESI и три графовых/структурных proxy-признака рассчитаны по текущему миллионному корпусу, а не по полной базе OpenAlex.
2. Выборка стратифицирована, поэтому частоты тем и ссылочные структуры могут отличаться от глобальной популяции.
3. `is_outlier_cluster` пока не является полноценным кластерным outlier-признаком.
4. `ppmi_domain_score` видит только ссылки на работы, присутствующие в текущем корпусе.
5. `distinct_venues_ratio` не является полной метрикой разнообразия входящих цитирований.
6. Для моделирования следует использовать только строки с рассчитанным `target_emergence`; строки с `NaN` предназначены для инференса или ожидают полного будущего окна.

Следующий этап после baseline — обучение CatBoost с временным разбиением данных и оценкой recall, PR-AUC и precision при требуемом recall. После перехода на полный корпус OpenAlex эти же определения признаков можно пересчитать на более полном графе данных.
