## pipeline/ — код пайплайна

### [__init__.py](pipeline/__init__.py)

Обозначает папку как Python-пакет. Содержит описание пакета, не запускает загрузку при импорте.

### [__main__.py](pipeline/__main__.py)

Точка входа для `python -m pipeline`. Разбирает команду и параметры, читает настройки, подключает логирование и вызывает нужный модуль.

Поддерживает действия `collect`, `targets`, `export`, `validate`, `status`. После `collect` и `targets` автоматически выполняет экспорт и проверку целостности, в том числе после обработанной остановки по лимиту. Поэтому после завершения сетевых запросов процесс может ещё несколько минут записывать локальные файлы.

Код завершения 0 означает успешное выполнение команды, 2 — обработанную паузу, например по лимиту или недоступности API. Неуспешная проверка `validate` возвращает 1; необработанные ошибки также завершают процесс с ошибкой. Успешный `collect` не означает, что метки рассчитаны.

### [common.py](pipeline/common.py)

Общие функции и API-клиент:

| Объект | Назначение |
|---|---|
| `configuration()` | Читает JSON-настройки, разрешает путь данных и создаёт папку |
| `api_key()` | Берёт ключ из окружения или .env |
| `Paused` | Исключение для возобновляемой остановки |
| `Client.get()` | Отправляет запросы, ограничивает частоту и количество попыток, повторяет запросы при сетевых ошибках и HTTP 5xx |
| `database()` | Открывает SQLite в режиме WAL и создаёт необходимые таблицы |
| `cached_get()` | Возвращает сохранённый ответ API или получает и кэширует новый |
| `short_id()` | Преобразует URL идентификатора в короткий ID |

При HTTP 429 клиент останавливается. Также останавливается при исчерпании лимита запуска или когда последний полученный остаток API не превышает 10. Он не ждёт следующего дня и не перезапускается автоматически. Ограничение запросов не является отдельным финансовым лимитом аккаунта.

### [collect.py](pipeline/collect.py)

Сбор и нормализация работ:

- `allocate()` распределяет целое количество строк по весам без потери итоговой суммы.
- `plan()` получает размеры доступных популяций, рассчитывает квоты и сохраняет план.
- `abstract()` восстанавливает текст из инвертированного индекса. Неверные или неполные позиции отклоняются.
- `normalize()` проверяет обязательные данные и формирует запись корпуса.
- `collect_stratum()` загружает одну группу выборки, исключает дубли и сохраняет страницу вместе с документами в транзакции.
- `collect()` управляет параллельными группами и сохранением полных Parquet-батчей.

В каждом году четыре домена. Physical Sciences разделён на Engineering и остальные области: всего пять непересекающихся групп на год, 85 за 17 лет. Доля Engineering берётся как максимум между её естественной долей и заданным минимумом 25%.

Фильтры: год в диапазоне, доступный восстановимый абстракт, непустая библиография и основная тема. Прочие пропуски сохраняются, если нет оснований восстановить значения.

Используется случайная выборка `sample<=10000` с seed, страницами по 100 работ и новым seed после завершения выборки. Во время проверки API сочетание sample+cursor не давало следующего курсора, поэтому здесь применяется обычная пагинация. Cursor pagination используется в авторской истории в `targets.py`.

Seed не фиксирует состояние самого OpenAlex: меняющийся индекс может давать изменения выборки между датами. Увеличение подквоты Engineering меняет представительность выборки.

### [targets.py](pipeline/targets.py)

Базовый расчёт целевой метки по полной популяции темы, а не по частотам внутри миллиона:

| Функция | Назначение |
|---|---|
| `growth()` | Сравнивает количество публикаций в окнах [t−2, t] и [t+3, t+5] |
| `topic_publications()` | Запрашивает /works с фильтром основной темы и group_by=publication_year; при текущих настройках годы 2008–2025 |
| `new_authors()` | Обходит минимальные поля работ темы курсорами и сохраняет первый известный год каждого автора |
| `label()` | Рассчитывает метки для строк pending, обновляет документы в SQLite |
| `historical_citations()` | Отдельная функция получения годовых количеств входящих цитирующих работ до cutoff; массовой CLI-команды для неё пока нет |

Текущий алгоритм: рост публикаций меньше 4 → Y=0. При росте не меньше 4 проверяется рост новых авторов: не меньше 2,5 → Y=1, иначе Y=0. При нулевой авторской базе метка остаётся None. Новый автор — автор с первой известной работой в данной основной теме в соответствующем окне.

Для авторского условия нужны дополнительные запросы: все доступные ранние годы темы до 2025 включительно, поля ID, год, authorships. Это не загрузка всего OpenAlex, но для крупных тем объём может быть существенным. Текущая реализация обрабатывает темы по очереди, а не сначала все публикационные агрегаты.

Предложенные в обсуждении минимумы 20 базовых публикаций и 10 новых авторов **ещё не реализованы**. Отдельного правила исключения зрелых тем нет. Контроль полноты авторских данных ограничен, поэтому написанный код ещё не означает готовую проверенную разметку всего корпуса.

### [export.py](pipeline/export.py)

- `SCHEMA` задаёт имена и типы 33 колонок Parquet.
- `checkpoint_batches()` сохраняет полные батчи по 50 000 строк во время сбора.
- `export()` читает SQLite частями, перезаписывает батчи, единый корпус и файлы обучения/инференса.
- `validate()` проверяет количество строк, дубли ID, критические пропуски и отсутствие меток у публикаций после 2020; сохраняет распределения и JSON-отчёт.

Каждый Parquet сначала пишется с расширением .tmp и заменяет целевой файл после закрытия. Весь набор выходных файлов не является одной атомарной транзакцией: прерванный экспорт следует повторить.

Название `openalex_corpus_1m.parquet` используется только при миллионе фактических строк и целевом total=1000000. В остальных случаях — `openalex_corpus_partial.parquet`, даже если небольшой эксперимент достиг собственного total.

Встроенная проверка после экспорта проверяет целостность без требования размера; отдельная команда `validate` дополнительно требует количество из config. Проверка точного совпадения всех 85 квот выполнялась отдельно при завершении сбора; она не входит в текущий `validate()`.

## data/ — база, результаты и логи

### state.sqlite

Основной источник состояния для дальнейшей работы. Содержит документы в JSON, квоты, страницы и кэши. Программа продолжает сбор по этой базе, а не по Parquet.

| Таблица | Поля и назначение |
|---|---|
| `metadata` | key/value: сохранённая конфигурация выборки и число строк, записанных в полные батчи |
| `strata` | name, filter, quota, population, seed, page: план и позиция каждой группы |
| `documents` | doc_id, stratum, payload: уникальный ID, группа и JSON нормализованной записи |
| `cache` | key, payload: сохранённые ответы API для агрегатов и обогащения |
| `topic_authors` | topic, author, first_year: первый известный год автора в теме; ключ темы также включает границу сканирования |
| `topic_cursor` | topic, cursor, complete: прогресс обхода авторской истории |

`state.sqlite-wal` — журнал транзакций, `state.sqlite-shm` — служебная память SQLite. Они могут появляться и исчезать при работе. Не удаляйте их вручную во время работы и не копируйте только основной файл как резервную копию активной базы: используйте SQLite backup либо корректно закройте соединения перед копированием.

### manifest.json

Описание последнего завершённого экспорта: фактическое и ожидаемое количество строк, имя единого файла, список батчей и `collection_complete`. Этот флаг относится к сбору, не к готовности меток.

### openalex_corpus_1m.parquet

Актуальный полный корпус. Одна строка — одна научная работа. Подходит для анализа исходных метаданных; сейчас ещё не является готовой обучающей матрицей.

### openalex_corpus_1m.validation.json

Отчёт последней проверки полного файла: rows, expected_rows, by_year, by_domain, engineering_by_year, targets, critical_nulls, duplicate_doc_ids, invalid_future_targets, passed. Отсутствие ключа поля в critical_nulls означает, что соответствующие пропуски не найдены.

### openalex_corpus_partial.parquet

Предыдущий экспорт на **963 990 работ**. После создания полного файла автоматически не удаляется. Для текущего анализа используйте файл с 1m в имени.

### openalex_corpus_partial.validation.json

Отчёт проверки именно старого частичного экспорта. Не описывает актуальный миллионный файл.

### batches/part-00000.parquet … part-00019.parquet

20 частей текущего корпуса, каждая по 50 000 строк. Одинаковая схема, сжатие zstd. Последний батч незавершённого сбора может быть меньше.

Батчи содержат те же документы, что и единый файл. **Нельзя объединять их с единым файлом как разные источники:** это продублирует данные. Восстановление батчей возможно из SQLite командой export.

### inference/candidates.parquet

Подмножество основного файла: 2021–2026, сейчас 352 938 строк. Метки None. Это кандидаты для последующего инференса, а не уже рассчитанные прогнозы.

### training/labeled.parquet

Подмножество с непустым target_emergence. Сейчас 0 строк: разметка не выполнялась. Кандидаты 2010–2020 пока остаются в основном файле с split=train_candidates.

### pipeline.log

Автоматический накопительный журнал CLI: время, уровень сообщения, квота/прогресс, паузы и результаты экспорта. INFO — обычная работа, WARNING может означать ожидаемую остановку по лимиту.

### collector.pid

ID процесса, сохранённый при отдельном фоновом запуске. Команда `python -m pipeline collect` этот файл не обновляет. Запись может быть устаревшей; файл не подтверждает активность процесса и не является блокировкой от двойного запуска.

### collector.stdout.log и collector.stderr.log

Перенаправленные стандартные потоки того фонового запуска. stdout может быть пустым; обычный Python logging по умолчанию попадает в stderr, поэтому наличие текста там не означает ошибку. При обычном запуске в терминале эти файлы не обновляются, сообщения видны в терминале и pipeline.log.

### smoke/

Изолированный пробный корпус на 50 реальных работах за 2010 год, не часть основного миллиона:

| Файл внутри smoke | Назначение |
|---|---|
| `state.sqlite` | Отдельная база тестового сбора |
| `manifest.json` | Описание тестового экспорта |
| `openalex_corpus_partial.parquet` | 50 работ; название partial обусловлено размером, а не провалом теста |
| `openalex_corpus_partial.validation.json` | Проверка тестового файла |

### Временные и автоматически создаваемые файлы

`*.parquet.tmp` — незавершённые экспорты, не готовые результаты. Папки `__pycache__/` и файлы `*.pyc` — автоматически создаваемый кэш Python; не содержат корпус. Папка `.venv/`, если вы создадите виртуальное окружение, содержит отдельный Python и зависимости и исключена из Git.

## Как запускать

Откройте терминал PowerShell в папке проекта:

```powershell
cd D:\TrendSpotting\TrendSpotting
python -m pip install -r requirements.txt
```

В команде `python -m pipeline collect`: python запускает интерпретатор, -m pipeline выполняет пакет через __main__.py, collect выбирает сбор данных.

| Команда | Действие |
|---|---|
| `python -m pipeline status` | Количество сохранённых работ и заполнение квот |
| `python -m pipeline collect` | Начать или продолжить сбор по SQLite; после полного сбора только переэкспортирует результат |
| `python -m pipeline targets` | Запросить дополнительные данные и рассчитать базовую разметку; затем автоматически экспортировать |
| `python -m pipeline export` | Пересоздать Parquet из SQLite без запросов к API |
| `python -m pipeline validate` | Проверить полный файл против total из config |
| `python -m unittest discover -s tests -v` | Выполнить шесть тестов без сетевых запросов |
| `python -m pipeline --help` | Показать справку |

Дополнительные параметры:

```powershell
python -m pipeline collect --max-requests 100
python -m pipeline collect --config another_config.json
python -m pipeline validate --file data/openalex_corpus_partial.parquet
```

`--max-requests` ограничивает HTTP-попытки конкретного запуска; по умолчанию 9900. Повторы при ошибках тоже учитываются. `--config` выбирает файл настроек относительно корня проекта. `--file` выбирает проверяемый Parquet относительно текущей папки.

Проверка старого partial при total=1000000 ожидаемо не пройдёт по количеству строк. Для сверки частичного размера используется встроенная проверка экспорта или отдельная конфигурация с нужным total.

Не запускайте одновременно collect, targets или export в одной папке данных: автоматической блокировки между отдельными процессами пока нет. После остановки по лимиту повторите нужную команду позднее; автоматического ожидания обновления бюджета нет. Сохранённые страницы и авторские курсоры позволяют продолжить работу.

## Движение данных и ограничения

```text
OpenAlex API → collect.py → SQLite
                              ↓
                targets.py: агрегаты и авторы → обновление Y в SQLite
                              ↓
                         export.py
                              ↓
         основной Parquet + батчи + training/ + inference/
                              ↓
                         validate()
```

`citations_at_cutoff` содержит цитирования на дату выгрузки, а не на исторический год статьи. Нельзя напрямую подавать это поле в исторические признаки. `counts_by_year` имеет ограниченную глубину истории; отсутствующие ранние годы нельзя считать нулями.

Даже запрос исторических входящих цитирований реконструирует прошлое по сегодняшнему графу. Классификация тем, авторские ID и полнота записей могут меняться. Корпус не является архивным снимком OpenAlex за каждый год.

Для продолжения работы сохраняйте SQLite, config, manifest и основной Parquet. Батчи, inference и training дублируют части основного корпуса, поэтому суммарный объём папки больше размера единого файла. Ничего из данных автоматически не удаляется после успешного экспорта.
