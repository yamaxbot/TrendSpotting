# TrendSpotting

Сервис поиска потенциальных слабых технологических сигналов в научных публикациях OpenAlex. Пользователь вводит направление; сайт собирает релевантные работы, рассчитывает признаки, ранжирует статьи CatBoost и показывает до 15 разных кандидатов с источниками и статистикой по годам.

## Как работает запрос

1. `on_demand_parsing/` нормализует запрос, находит исходные работы и темы OpenAlex, расширяет поиск, удаляет дубли и сохраняет корпус в `website/data/`.
2. `preprocessing/create_features.py` считает признаки статьи и её научного окружения. Исторические признаки зависят от корпуса, а не только от текста одной статьи.
3. `website/main.py` загружает `outputs/catboost_splits/random/catboost_model.cbm`, рассчитывает вероятности, исключает обзоры, проверяет соответствие запросу и выбирает до 15 непохожих работ. Порог берётся из соседнего `metrics.json`.
4. `website/trends/` показывает карточки; для каждой карточки отдельно ищет близкие публикации и более широкую тематическую статистику. `website/query_llm.py` переводит названия и формирует описание по аннотации и подтверждённым факторам.

Модель оценивает **статью-кандидат**, а не существование целого тренда. График и дополнительные источники собираются отдельно. Отсутствие полной статистики или малого числа близких работ не следует трактовать как отсутствие исследований. Данные за 2026 год неполные.

| Папка | Назначение |

| [`on_demand_parsing/`](on_demand_parsing/README.md) | Поиск и очистка публикаций для нового запроса |

Офлайн-сбор корпуса и обучение **не запускаются** при поиске на сайте. Локальные Parquet, кэши и ключи исключены из Git и Docker-образа. Старые подробные заметки внутри папок помечены как исторические; актуальные точки входа описаны в их `README.md`.

## Запуск через Docker Compose

Нужен запущенный Docker Engine или Docker Desktop. Из корня репозитория:

1. Заполните `.env` по образцу [`.env.example`](.env.example). `OPENALEX_API_KEY` нужен для нового поиска; `KIE_API_KEY` — для нормализации запроса, проверки релевантности и текстовых описаний.
2. Выполните `docker compose up --build -d`.
3. Откройте <http://127.0.0.1:8000/>. Логи: `docker compose logs -f web`.
4. Остановка: `docker compose down`. Не добавляйте `-v`, если хотите сохранить результаты и кэш.

Образ включает код и выбранную модель, но не большой обучающий корпус. При первом поиске `sentence-transformers` скачает модель эмбеддингов. Результаты, отладочные JSON и кэш модели сохраняются в Docker-томах. Проверка Compose: `docker compose config --quiet`.

Compose запускает **один** Gunicorn-воркер: статусы фоновых задач сейчас хранятся в памяти процесса. При перезапуске незавершённый поиск нужно повторить; несколько реплик без общей очереди не поддерживаются. По умолчанию порт доступен только локально. Для внешнего доступа задайте `DJANGO_DEBUG=0`, сильный `DJANGO_SECRET_KEY`, `DJANGO_ALLOWED_HOSTS`, `HOST_BIND` и HTTPS через внешний прокси. Локальные значения из `.env.example` не подходят для публичного сервера.

## Запуск без Docker

На Python 3.11+ установите `pip install -r requirements.txt`, задайте ключи в `.env` и выполните `python website/manage.py runserver`. Точка входа сайта — `website/manage.py`; Python-команды запускайте из корня проекта, если в документации папки не указано иное.

## Проверка и эксперименты

`python website/manage.py test trends --noinput` проверяет сайт; `python -m unittest on_demand_parsing.test_optimization` — парсер. Их можно запустить в образе: `docker compose run --rm --no-deps web python manage.py test trends --noinput`.

Сайт использует модель, обученную со случайным разделением (тестовый ROC-AUC 0,945; PR-AUC 0,780). При разделении по времени тестовый ROC-AUC 0,609 и PR-AUC 0,121. Это существенное ограничение переноса на новые годы; метрики и различия экспериментов описаны в [`outputs/README.md`](outputs/README.md). Проценты на карточках — оценки модели, не доказанная вероятность возникновения тренда.
